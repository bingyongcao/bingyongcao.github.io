如果只用一句话概括这一轮 M3 的实测感受，那就是：**这个版本我愿意主动推荐给别人用**。

之前 M2.7 我一直处在"继续观望"的状态，但 M3 出来之后，无论是在代码能力还是多模态生成上，都能明显感觉到这一代模型是真的在往"能直接拿来干活"的方向走。下面我把这次实测里几个比较有代表性的场景和结论整理一下。

## 先说结论

1. **代码能力**有惊喜：在一个相对复杂的 .NET 拖拽 UI 任务里，M3 的完成度明显高于 GPT 5.4。
2. **多模态生成**进步明显：从 M2.7 到 M3，图片生成质量是肉眼可见的跨越。
3. **迭代节奏**是加分项：MiniMax Code 保持日更，能力上限还在被持续刷新。

下面按我实际跑过的几个场景展开说。

## 1. 代码能力：复杂 .NET 交互也能一次跑通

最近正好遇到一个比较复杂的交互要通过 .NET 来实现，所以借此机会拿 M3 测一下它的代码能力，跟 GPT 5.4 同台比一比。

我没有报太大的期待，但出来的效果确实让我意外，完成度非常高。除了有一个 `Move over` 高亮细节上的小问题之外，其他我所描述的功能都实现了，而且视觉效果也相当不错。提示词如下：

> 为新功能测试新建一个选项卡。我附上的图片是一个 UI 草稿，界面分为两部分：左侧是一个固定的条目布局画布，包含 9 列 4 行，每个单元格可以填充一个标签项；右侧是标签项列表。用户可以将标签项拖拽到布局画布中，也可以取消已占用的标签项，使其返回到标签列表中。当用户在已填充的单元格上覆盖一个新标签时，会先取消之前的标签，再将新标签添加到该单元格。用户还可以通过套索拖拽（类似文件区域选择）选中多个已填充的单元格，以覆盖其他单元格。

## 3. 迭代速度：日更的版本节奏

MiniMax Code 这边基本保持日更，意味着即便你现在用它有一些边界没覆盖到，下一个版本大概率就会被补上。这种节奏对实际使用者来说，是非常实在的安全感。
